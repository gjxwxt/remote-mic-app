# YK-8E00 macOS 实验候选

当前适用分支：`codex/yk8e00-upstream-sync`。上游基线：`cba59c43163320d9b93a54d9cbcef766b764c84d`。此前 `codex/yk8e00-sbc-20261121`、基线 `8f03bdd4f80adc59e2c2c098a55fb3aacc6dff60` 的记录仅用于追溯。

本机候选接入 YK-8E00 的首次设置、连接状态和实时语音。普通键保留系统原生行为，并可供引导验收。旧款 RC86 和 Windows 不在本候选范围内。共同门槛见 [硬件合同](HardwareCompatibilityContract.md) 和 [音频合同](HardwareVoiceAudioContract.md)。

## 当前边界

| 项目 | 状态 |
| --- | --- |
| 型号准入 | IOHID VID `0094`、PID `0013`；同名设备不作为身份 |
| 格式 | 报告 `0x5A`、121字节；两帧60字节普通SBC，16kHz单声道 |
| 解码 | 内置 Google libsbc，严格格式及CRC；不依赖Python或FFmpeg |
| 输出 | 现有虚拟麦克风及 Fn 按住语音会话；连接后可预备输出，启动音频先保留约 500 ms，再按采集顺序播放。这样给输入工具打开麦克风的时间，设备实测的最佳值仍待核验。 |
| 音量 | 固定8倍增益、峰值限幅；复用回放验证的水平，真机仍待测 |
| 语音开始 | 首个有效音频报告；物理按下时刻未知 |
| 语音结束 | **物理松开信号未确认**；停流300ms后排空，采集收尾标记forced/unknown |
| 普通键 | 从本设备的标准键盘报告及 Consumer usage 观察新按下边沿；系统原生行为保留。SayAll 自定义映射、连发验证及学习未适配。 |
| 照片/画布 | 未增加型号画布，不套用小米图片 |
| 电池/触摸 | 未声明支持 |
| Windows | 未实现、未测试 |

停流不能区分正常松开与丢失连接。300ms内再次按下可能合并为一次输入。此边界未解决前不得称为正式兼容、推荐或发布候选。

## 前置条件

1. 在系统蓝牙中配对这只YK-8E00，断开旧RC86；同时匹配到多只时适配器拒绝采用。
2. 通过项目原生本地打包入口构建公开开发自用包。此包仅在构建者本机测试，不作分发资产。
3. 在系统设置中为当前SayAll授予输入监控和辅助功能；签名身份变化可能需要重新授权。
4. 在SayAll选择虚拟输出，在豆包选择同一个`MiRemoteV 2ch`；语音键模式使用Fn按住，关闭Fn点按模式。
5. 首次设置时在设备页选择 YK-8E00，再用方向键完成按键检查。语音测试使用页面自己的文本框。已完成引导时在“设置 → 连接”检查 YK-8E00 和音频路线，然后选一个空白文本框。现有录音保存偏好保持原样。

## 逐项实机测试

| 用例 | 操作与预期 | 失败判定 |
| --- | --- | --- |
| 物理边沿 | 无声按住语音键2秒再松开，核对报告及收尾 | 无法确认松开来源时继续标记未知，不凭停流宣布正常 |
| 首次短句 | 按住语音键说固定短句后松开；无需手动按键盘Fn，豆包应出字 | 首字/尾字缺失、焦点变化、未出字 |
| 快速按下/释放 | 重复10次，观察Fn不残留 | 收音或Fn卡住，第二次才成功 |
| 连续两句 | 分别间隔100ms、500ms、2秒，检查独立结果 | 合并会话、首字缺失、旧数据进入新会话 |
| 较长输入 | 连续说30秒，检查无断流及尾字完整 | CRC失败、音频中断或不完整 |
| 断连/恢复 | 收音中关闭遥控器连接，再重连并说一句 | 假正常收尾、Fn残留、重连首句失败 |
| 权限撤销 | 撤销输入监控或辅助功能，再恢复 | 无错误边界或恢复后不能重新接收 |
| 睡眠/唤醒 | 收音中休眠，再唤醒测试 | 旧流复用、按键残留 |
| 跨硬件 | 与RC003、桌面麦、手机语音分别切换 | 两路同时持有Fn、桌面麦被偷偷启用或旧流混入 |
| 普通键回归 | 四方向、确定、返回、音量各按3次 | 原生行为被本适配器改变；自定义映射不列为已通过 |

后台SayAll、前台SayAll设置页和前台其他输入框分别执行首次短句。输入工具尚未启动时验证失败和恢复，不以虚拟音频已排空当作文字成功。

## 日志与自动化

通过SayAll既有诊断入口收集脱敏日志。关注`SKYWORTH HID`、`SKYWORTH VOICE`及相同来源的`MOBILE VOICE`和音频排空日志。日志不记录原始音频、文字、设备地址或名称。

- `phase=ready`只证明 IOHID 设备已打开。即使条件允许预备虚拟输出，也需要真实按键和语音测试。
- `trigger_observation=first_audio`明确表示没有物理按下观测。
- `reason=release_unobserved completion=forced`表示收尾尚未确认，不能用后续输出队列的正常排空覆盖这个采集边界。
- SBC测试使用合成正弦向量及独立FFmpeg参考，覆盖CRC、错布局、逐包顺序、状态回滚和重置。
- 传输测试覆盖重复包保序、启动拒绝、同一按键不重复计数、中断后余包丢弃及停流后重启。真实 IOHID 回调、遥控器按键时序和豆包上屏需要实机检查。

此前独立内存实验中，用户确认同一设备语音清楚，豆包出字成功。此后本机 build 176 的真实引导中有四次语音尝试达到文字门槛，也出现过 CoreAudio 改绑输出后的 `playback_not_ready`。上述结果属于旧基线，更新后的候选仍须重新核对真实豆包上屏、首尾字和短间隔会话。
